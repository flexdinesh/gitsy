# Plan: add `--sync` to auto fast-forward safe repos

## Summary
Add a `--sync` flag that, after fetching, automatically fast-forwards every discovered repo/worktree whose current branch can advance to its upstream with zero risk of conflict. Non-trivial cases are left untouched and reported. gitsy gains its first mutating operation, gated behind an explicit flag.

## Safety definition (fast-forward only)
A repo is auto-updated iff **all** hold (all derivable from existing `parseStatus`):
- `branch` defined and `branch.name !== ""` (not detached HEAD)
- `branch.upstream` set and `!branch.gone`
- `branch.behind > 0` (something to pull)
- `branch.ahead === 0` (not diverged)
- `status.items.length === 0` (clean working tree — dirty repos skipped)

This maps exactly to `git merge --ff-only`; a true fast-forward cannot conflict.

## Key changes
1. **src/args.ts** — add `sync: boolean` (default false), parse `--sync`, document in USAGE.
2. **src/git.ts** — add `fastForward(repoPath): GitResult` running `git -C <path> merge --ff-only`.
3. **src/ui/table.ts** — extend `RepoFetchState` with a `syncing` state and a sync outcome on `done`; render `⤓ synced ↓N` (green) / `⚠ sync failed`.
4. **src/ui/App.ts** — after fetch + status, if `sync` and FF-safe → syncing → `fastForward` → re-run status → done with outcome. Thread `sync` through `AppProps`.
5. **src/index.ts** — pass `options.sync`; force fetch on (`noFetch: options.sync ? false : options.noFetch`).
6. **README.md** — document `--sync` + usage example.

## Tests / verification

- `test/integration.test.ts`: origin + clone, advance origin, FF success asserted; diverged branch → `merge --ff-only` refused, repo unchanged.
- `pnpm test` and `pnpm typecheck`.

## Decisions made by user
- Flag name: **`--sync`**
- Dirty working tree → **skip**
- `--no-fetch` → **overridden**; `--sync` always fetches first
- Scope → **all FF-safe discovered repos and worktrees**
- No confirmation; update silently and report results

## Tradeoffs & risks
- Read-only → mutating shift. Mitigated by explicit opt-in flag and strict FF-only semantics.
- Forcing fetch over `--no-fetch` is a silent override; acceptable since FF on stale refs is meaningless.
- Worktrees FF'd independently against their own upstream — no cross-worktree interference.
- Dirty-skip may surprise users; chosen for predictability.
